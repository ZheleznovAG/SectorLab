# ADR-023 — Конец выстрела в клиентском представлении

**Дата:** 2026-10-27
**Статус:** принято

## Контекст и проблема

Ревью R-02: клиент слышит выстрел по счётчику Shots, но UnitAttack отключён и линию никто не рисует.
Для направления огня недостаточно знать только число выстрелов и позиции бойцов.

## Варианты

- Клиент самостоятельно выбирает ближайшую цель: не требует сети, но может показывать неверный бой.
- Очередь надёжных визуальных событий: сложнее, нужна политика поздних событий и дубликатов.
- Сохранить в снимке конец последнего выстрела: достаточно для короткого сигнала текущего боя.

## Решение

UnitView передаёт X/Z подтверждённого конца последнего выстрела. ClientUnitView рисует линию
при увеличении Shots того же живого поколения и матча и выключает её по unscaled времени.
Первый кадр, respawn, новый матч, смерть и разрыв задают/сбрасывают baseline без проигрывания истории.
UnitAttack, NavMesh и локальный расчёт урона клиента остаются отключёнными.

Формат слота вырос с 28 до 36 байт; полный обычный пакет — 277 байт. Протокол **v3**, версия игры
**1.3.0/code 4**. Обоим игрокам требуется одна совместимая сборка.

## Последствия

Это краткая обратная связь по последнему известному выстрелу, без гарантии показать каждый
выстрел при потере UDP. Надёжная доставка истории не нужна. Конечные координаты валидируются
до применения всего кадра. Высота линии берётся из локального представления бойца.

## Проверка

Round trip конца выстрела, NaN в поздней записи не меняет кадр, v2 отвергается. Клиент рисует
подтверждённое направление, гасит линию, не повторяет её на дубликате/respawn/новом матче и
никогда не включает симуляцию. Затем две реальные Windows-копии через UTP.
