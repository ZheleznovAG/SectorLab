# ADR-001: контракт v1.0 и сохранение проверенного baseline

Дата: 2026-10-11. Статус: принято в пределах текущего поручения.

## Контекст

В HEAD `1c8754d` остался прототип R4/R5 с целью уничтожения команды. В рабочем
дереве есть ранее проверенные fixes и новый контракт Relay Skirmish.
Исторические документы запрещали автономную реализацию/коммиты и оставляли
геймдизайн открытым. Новая прямая инструкция AGENTS.md явно заменяет этот режим.

## Решение

Сохранить исходные 35 коммитов и Main/prefab/meta. Новые инструкции и ТЗ
зафиксировать как документацию; существующие fixes боя, навигации и выбора
сохранить отдельными настоящими локальными коммитами после регрессии.
Полный результат тестов относится к совокупному входному дереву, это явно
отражено через исходный HEAD + SHA-256 файлов; не приписывать его промежуточным
чистым коммитам. Push не выполняется.

Для нового поведения источники — `docs/agent_execution/02_GAME_DESIGN.md`,
`03_REQUIREMENTS.md`, `06_DELIVERY_PLAN.md`, `09_ACCEPTANCE.md`. Старые docs
сохраняются как история с указателями на актуальное ТЗ. Наличие контракта
не означает, что целевые функции реализованы.

В описании узлов соседствовали требования «нужен свой боец для очков» и
«после ухода своих полный узел продолжает давать очки». Выбрано второе явное
правило из того же абзаца: A/B при полном захвате и без противника дают очки
пустыми, C лечит только присутствующего союзника. Убрана противоречащая фраза;
баланс и числовые параметры не изменены. W2 должен покрыть пустой узел,
contest и начало нейтрализации отдельными тестами.

## Альтернативы и последствия

Разворачивать ZIP поверх дерева рискованно: актуальные инструкции новее ZIP.
Возврат к ручному режиму противоречил бы текущему поручению. Требование
постоянного гарнизона изменило бы явно заданную механику ухода с узла.

Baseline проверен 9 EditMode + 38 PlayMode и Android incremental build. Он сохраняет простую работающую основу, на которой последовательно строятся
W1–W9. Сначала W1 заменяет условия исхода и вводит время/паузу, затем W2 добавляет узлы.

## Проверка

`docs/agent_execution/EVIDENCE_REPORT.md`: реальные CLI-ответы тестов,
BuildReport, входные SHA и ограничения. `IMPLEMENTATION_STATUS.md`: полный
реестр FR/NFR, actual commits и следующий шаг. Старые тесты уничтожения команды
при W1 заменяются проверками нового контракта; два конкурирующих условия
завершения матча не сохраняются.
