# ADR-021 — Явный контент платформы и проверка артефакта

**Дата:** 2026-10-27
**Статус:** принято

## Контекст и проблема

Ревью R-07 обнаружило APK с каталогом Android, ссылками StandaloneWindows64 и без бандлов.
Проверка префикса `assets/aa/` считала такой APK исправным. Первый content build также
останавливался модальным вопросом Addressables о диагностическом layout (R-06).

## Варианты

- Полагаться на автоматическую сборку Addressables внутри Player build: мало кода, но момент
  вычисления platform profile зависит от состояния Editor, а содержимое APK не проверяется.
- Явно выбрать target, дождаться Editor, собрать контент и сверить файлы готового Player с
  отпечатками content build: немного общего tooling для Android/Windows, без нового runtime-слоя.

## Решение

Оба build wrapper используют одну подготовку target/content. Editor-инструмент записывает
пути, размеры и SHA-256 бандлов из публичного FileRegistry результата Addressables и локального
каталога/settings. Player должен содержать эти файлы без изменений; bundle paths принадлежат
выбранной платформе. Каталог без бандлов, другая платформа и устаревшие файлы отклоняются.

Перед content build очищается кеш profile properties. Включается публичный проектный параметр
`ProjectConfigData.GenerateBuildLayout`: это диагностический файл в Library, не runtime-сервис;
первый запуск больше не требует ответа на модальное окно. После domain reload сначала
проверяется готовность endpoint; повторять произвольные мутации автоматически нельзя.

## Последствия

Успех Unity build и проверка упаковки — отдельные результаты. Старые evidence не перезаписываются.
Наличие файлов не заменяет проверку загрузки шести слотов на физическом Android. Настройка
layout остаётся включённой в локальном кеше Editor; она не добавляет сетевую диагностику в APK.

## Проверка

Python-регрессии: catalog-only, отсутствующий/изменённый bundle, изменённый каталог, другая
платформа, выход пути за каталог. Затем Windows → Android и Android → Windows через sl.py,
сверка manifest/артефакта и отдельная двухпроцессная приёмка. Телефон отмечается отдельно.
