# ADR-014: Unity Transport напрямую, без Netcode for GameObjects

Дата: 2026-10-22 (решение реализовано 21.10.2026 в `71a79ef`, записано задним числом). Статус: принято.

## Контекст

[ADR-013](013-network-readiness.md) выбрал авторитетный хост и назвал транспортом Netcode for GameObjects (NGO)
поверх Unity Transport. К моменту подключения транспорта модель уже была готова без NGO.
Приказы — 17-байтные данные с проверкой на хосте (`MatchCommands`), состояние — два бинарных
снимка (`MatchSnapshot`, `UnitsSnapshot`), а сессии (`HostSession`, `ClientSession`) работают поверх
интерфейса `IMessageChannel` и проверены через `LoopbackChannel`.

## Варианты

- **NGO.** `NetworkObject` на юнитах, `NetworkTransform`, RPC. Минусы: юниты создаются через Addressables
  с арендой (ADR-005), а NGO требует собственного спавна префабов и регистрации. Свои синхронизации
  дублировали бы `MatchModel` и снимки. Объём зависимостей и правок сцены велик для 1×1.
- **Unity Transport (UTP) напрямую.** `NetworkDriver` с двумя pipeline: reliable sequenced для приказов
  и unreliable sequenced для снимков. Один класс `UtpChannel` (~100 строк) реализует `IMessageChannel`.
  Минусы: соединение, повтор состояния и обрыв обрабатываем сами.
- **Сырые сокеты .NET.** Нет надёжной доставки и фрагментации; на мобильных больше сюрпризов.

## Решение

UTP напрямую (`com.unity.transport` 6.6.0). Снимки идут ненадёжно: важен только последний. Поэтому хост
повторяет состояние каждые 0,25 с, пока часы стоят (пауза, ожидание, итог), — с 22.10 (`b210e28`).
Приказы идут надёжно и по порядку. Один удалённый игрок; лишние соединения хост сразу отключает.

## Последствия

- Нет сетевых объектов на юнитах: клиент держит обычные юниты как прокси и ставит их по снимку.
  Интерполяции пока нет — юниты движутся рывками по 10 Гц.
- Relay и NAT не решены: игра только в одной локальной сети по IPv4. Для игры через интернет нужен relay
  (например, UGS Relay; UTP его поддерживает) — отдельным решением.
- Нет шифрования и аутентификации; защита — только проверка приказов хостом.
- Пересмотреть, если появятся больше двух игроков, наблюдатели или нужда в rollback/prediction.

## Проверка

`UtpChannelTests` — реальный UDP на localhost: обмен, один игрок, хост `Main` ждёт соперника. `NetworkMatchTests` и `NetworkSessionTests` — через loopback. E2E 21.10: Editor-хост и Windows-клиент
на одном ПК ([скриншоты](../evidence/E2E-host-blue.png)).
