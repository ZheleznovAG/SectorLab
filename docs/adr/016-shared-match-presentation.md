# ADR-016 — единое состояние представления матча

**Дата:** 2026-10-26  
**Статус:** принято

## Контекст и проблема

Аудит A1–A3 обнаружил, что HUD узлов читает R3, графика узлов — локальный захват,
карточки бойцов — локальный lifecycle, а звук итога — событие симуляции.
На клиенте симуляция выключена: полученное состояние не полностью видно игроку.

## Варианты

- **A:** отдельно исправлять каждый клиентский компонент, дублируя представление.
- **B:** расширить существующий MatchModel данными слотов и использовать его для обеих ролей.

## Решение

Выбран B. `UnitView` содержит состояние слота без Unity-объектов: жизнь, HP,
респаун, поколение экземпляра, координаты и счётчик выстрелов. `UnitLifecycle`
публикует авторитетные данные, клиент получает их из снимков.

`MatchModel.Commit` обозначает конец согласованного обновления. Потребитель,
которому нужны несколько полей одновременно, читает модель после Commit.
Существующие R3-свойства продолжают подавлять неизменившиеся значения.

`RelayPoint.Show` рисует `RelayView` без изменения правил захвата. Выбор проверяет
состояние слота; прокси может иметь 0 HP без локального Died/респауна. Итоговый звук
следит за исходом модели с перспективой текущей стороны.

## Последствия

Модель чтения общая, симуляция остаётся только на хосте/в одиночном режиме.
Камера, выделение и mute локальны. Координаты и события всех слотов потребуют
полного снимка протокола следующего этапа; старый снимок передаёт только живых.

## Проверка

`ClientPresentationTests`: фактическое кольцо узла, выбор и карточка погибшего
бойца, возвращение прокси, повтор результата и новый матч. Исходные три регрессии
упали на прежней реализации (`tests-client-view-red-playmode.json`).
Одиночный режим дополнительно защищают BattleHudTests, RelayPointTests и MatchAudioTests.
