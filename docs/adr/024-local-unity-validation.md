# ADR-024 — Локальные Unity-проверки без обязательных облачных сервисов

**Дата:** 2026-10-27

**Статус:** принято

## Контекст и проблема

Unity-тесты и сборки уже выполняются локально с проверяемыми отчётами. Автоматический GameCI
останавливается на отсутствии лицензирующих секретов. Внешний разбор предложил Unity Build
Automation, но владелец явно отказался от подключения сервисов Unity и новых облачных зависимостей.

## Варианты

- Подключить облачное лицензирование и новый сервис: требует внешней настройки и противоречит решению владельца.
- Оставить быстрые GitHub-проверки и локальный Unity: использует действующие инструменты; полного автоматического Unity PR-gate нет.

## Решение

Python, гигиена и приватность проверяются GitHub Actions на push/PR. Unity EditMode/PlayMode,
Windows/Android build и приёмка выполняются локально через `Tools/sl.py` в установленном Editor.
GameCI остаётся только как ручной эксперимент. Его secrets не нужны обычному рабочему процессу.
План подключения Unity Build Automation отменён. Новые сервисы Unity без отдельного решения
владельца не подключаются.

## Последствия

Push/PR не падает из-за отсутствия облачной лицензии. Сохраняются локальные команды, полные
тесты и evidence. Локальный результат сам по себе не блокирует merge на GitHub: обязательного
автоматического Unity-gate нет. Это принятое ограничение, а не закрытие R-03 успешным облачным тестом.

## Проверка

Actionlint и гигиена репозитория проходят. В `tests.yml` единственный триггер — `workflow_dispatch`;
на push запускается `checks.yml`. Последние успешные Unity evidence остаются неизменными.
