## Как принимать дальнейшие решения

1. Назвать реальную проблему.
2. Сравнить минимум два простых варианта, если вопрос существенный.
3. При недостатке информации сделать короткий spike.
4. Записать решение, причину и ограничение.
5. Пересматривать решение при появлении новых данных.

Для простого перемещения куба отдельный ADR не нужен. Для выбора системы ввода, схемы команд или внедрения контейнера зависимостей — вполне уместен.
