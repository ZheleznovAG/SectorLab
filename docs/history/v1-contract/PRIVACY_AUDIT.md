# Проверка приватности перед продолжением разработки

Проверено 2026-10-12 по местному времени: исходный HEAD
`6fa7d41b99fc53073609737d87e8f095ea809efe`. Проверка охватывает 70 доступных
коммитов всех локальных refs, 786 уникальных Git blobs, 470 отслеживаемых файлов
и 29 доступных LFS objects. Кеши Unity, APK и локальные архивы не входят в Git.

## Фактические находки

- Gitleaks 8.30.1 с исходными правилами: **0 секретов**. Сканер сообщает
  68 коммитов с анализируемым содержимым, около 5,66 MB. Отдельная проверка
  blobs охватила все 70 коммитов, включая метаданные и LFS.
- Пароли/ключи API, приватные ключи, signing keystore, credentials в URL,
  JWT, SSID/BSSID/IMEI/IMSI не обнаружены. Серийный номер подключённого телефона
  искался точным сравнением без записи номера в отчёт: находок нет.
- **Личные метаданные найдены**: имя/личная почта автора Git и путь Windows
  с именем профиля. В текущих документах/отчётах было 57 путей в 47 файлах;
  в истории такие пути есть в 87 версиях blobs. Самих значений здесь нет.
- GitHub API подтвердил публичность remote; опубликованная main во время
  проверки указывала на `404469a5653e0cbd6d2c5df676fa6b323c70aed3`.
  Следовательно, исторические метаданные уже доступны извне.
- Device captures показывают только SectorLab; model/Android version, package
  ID, PID, timestamps и SHA являются необходимыми техническими данными проверки.

Почта/имя позволяют связать публичный профиль с личностью, облегчают спам и
адресный фишинг. Локальный путь раскрывает имя профиля. Эти данные сами по себе
не дают доступа к компьютеру или аккаунтам. Это отличается от утечки действующего
секрета, которую данный аудит не выявил.

## Как повторить

Установить официальный [Gitleaks](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1)
8.30.1 в PATH либо `%LOCALAPPDATA%/SectorLab/Tools/gitleaks/8.30.1/gitleaks.exe`.
При аудите ZIP загружен с официального release, SHA-256 сравнен с checksums.txt.
Исполняемый файл и локальные отчёты скачивания не добавлены в Git.

```powershell
git config --local user.name ZheleznovAG
git config --local user.email ZheleznovAG@users.noreply.github.com
git config --local core.hooksPath .githooks
./Tools/check-privacy.ps1
./Tools/check-privacy.ps1 -Staged
./Tools/check-repository.ps1
```

`check-privacy` проверяет публикуемые текущие файлы или индекс. Исторический scan
секретов отдельно выполняется с исходной конфигурацией Gitleaks, без новых PII rules:

```powershell
gitleaks git --log-opts=--all --redact=100 --no-banner --report-format=json --report-path=Temp/privacy-history.json .
```

После появления `.gitleaks.toml` команда использует дополнительные PII rules и
обоснованно найдёт исторические пути; для сравнения исходного secret scan нужно
запускать с конфигурацией `extend.useDefault=true` вне репозитория. Это не причина
исключать найденные личные пути из текущего privacy gate.

## Исходная граница очистки истории (до разрешённой замены)

До разрешённой замены текущее дерево было очищено, опубликованная история ещё
содержала личные метаданные. NFR-010 тогда нельзя было считать выполненным.
Переписывание меняет SHA. Для полной очистки нужен отдельный подготовленный clone,
редактирование author/committer и paths во всех версиях, проверка содержимого,
карта старых/новых SHA и контролируемый `force-with-lease` для main.
Исходный рабочий каталог и локальная резервная копия сохраняются.

AGENTS.md прямо запрещает самостоятельный force push/подмену истории; этот
отдельный шаг требует явного изменения разрешения пользователем. Обновление
remote не стирает чужие clones/forks и кеши. Эти ограничения описаны в
[официальной инструкции GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

Очищенный кандидат подготовлен в отдельном локальном bare clone, исходный репозиторий
не переписан. [Проверка](../../evidence/privacy-history-candidate.json): 71/71 коммит сохранён,
HEAD кандидата 762c1e33af79dcfacc85d12f86fdd724cf89d480; текущее дерево побайтно совпадает
с a992dfc7b13b71d829cb0942b1e19b6409e61ef0 (tree 00f9a79ef221092f2e2131e597c4af5ee1cb709f).
Gitleaks с новыми privacy rules: 0 findings; все author/committer используют публичный
ник/noreply. Полный исходный Git bundle проверен, карта SHA находится вне Git.
Первый callback не запустился из-за UTF-8 BOM; исходная копия оставалась неизменной,
BOM удалён и последующий rewrite/scan успешен. Ничего не опубликовано.
При разрешении пользователя кандидат нужно обновить до последнего HEAD,
сверить remote непосредственно перед force-with-lease и документировать переход SHA.

12.10.2026 пользователь ответил: «Да, очистить историю и выполнить force-with-lease».
Это разовое исключение из запрета переписывания/публикации main для удаления
приватных метаданных. Новые самостоятельные push и публикация APK этим не разрешены.
Кандидат обновляется до текущего committed HEAD с полным backup Git/LFS вне репозитория,
проверкой числа коммитов, сообщений/дат/топологии и неизменности кода/ассетов.
Перед заменой main повторно сверяется live remote и применяется точный lease.
