# 06. План реализации v1.0: проверяемые рабочие пакеты

## Общая стратегия

**Сначала зафиксировать исходную правду, потом один законченный игровой цикл, затем технологии и полировка.** Задачи агента упорядочены зависимостями. Не выдавать скриптовый прогон за живую проверку геймплея, не закладывать сценические изменения «на память» без проверки Game View. Все новые правила в `02_GAME_DESIGN.md` и `03_REQUIREMENTS.md`.

Порядок ниже — **логический**, допускает маленькие перестановки после ADR. Нет жёстких календарных сроков. Каждый пакет содержит несколько небольших реальных коммитов, а не одну гигантскую правку.

## W0 — безопасный baseline, незакоммиченные исправления

При учёте исполнения ID задач берутся из `WORK_ITEMS.csv`. Подпункты W0 ниже
изначально имеют другую нумерацию: CSV W0.2 = бой, W0.3 = навигация,
W0.4 = выбор, W0.5 = документы; регрессия/APK относятся к проверке всего W0.
Фактическое завершение и SHA — в `IMPLEMENTATION_STATUS.md`.

**Зависимости:** доступ к истинной рабочей копии и Git LFS.

- W0.1 Инвентаризировать git, Unity, assets, тесты. Сохранить копию незакоммиченных изменений, не затирать их.
- W0.2 Разобрать имеющиеся `UnitAttack`, `UnitMovement`, `UnitCommander` и тесты. Сохранить текущие улучшения line-of-sight, навигации, наведения, повторных попыток и честно сгруппировать по отдельным багфикс-коммитам. При необходимости использовать выборочную подготовку hunks (`git add -p`).
- W0.3 Обновить сопутствующие исторические документы и PNG LFS **только при истинном содержательном изменении**. Проверить Git LFS, `.meta` и чистоту дерева.
- W0.4 Перезапустить текущие тесты (из журнала 9+38) и APK-build. Зафиксировать реальные логи либо BLOCKED.
- W0.5 Зафиксировать изменение режима агента и утверждённое ТЗ в одном документационном коммите.

**Gate G0:** есть воспроизводимый хеш baseline, незакоммиченные пользовательские изменения не потеряны, история сохранена; статус тестов честно записан.

## W1 — контроль времени и игровой матч

- W1.1 Вынести правила матча из `BattleController` в тестируемые модели: время, очки, `InProgress/Victory/Defeat/Draw`.
- W1.2 Игровое время/пауза: один источник `deltaTime`; Reset и таймауты; без самостоятельных таймеров по `Time.time` для доменных правил.
- W1.3 Тесты 45 очков, 180 секунд, одновременное достижение, одинаковый счёт/ничья, отсутствие движения времени при pause.
- W1.4 Обновить UI результата и перезапуск без потери текущих функций до появления узлов (временный имитационный тестовый источник очков).

**Gate G1:** матч можно провести по тестовому счёту и завершить всеми четырьмя исходами, нет зависимости правил от FPS.

## W2 — захват и взаимодействие с объектами

- W2.1 Добавить `RelayConfig` и чистую модель прогресса `[-1; +1]`, contest, пустой узел.
- W2.2 Тесты нейтрального захвата (5 с), перехвата (до 10 с), contest, уходов и смертей, границы владения.
- W2.3 Создать три узла A/B/C из примитивов, коллайдеры/радиус, Scene NavMesh и визуальную индикацию прогресса/команд.
- W2.4 Из выбранного юнита реализовать команду движения к узлу; отказаться от невозможных целей корректно.
- W2.5 Два очковых узла обновляют счёт, ремонтный лечит; добавить `Health.Heal` с EditMode tests. Переменную скорость симуляции проверить.

**Gate G2:** игрок может занять 3 узла, увидеть спор/нейтрализацию/перекрас, набрать очки; нет начисления через contest и сквозь паузу.

## W3 — противник и короткая полноценная партия

- W3.1 Простая модель целей AI без читерства и с ограничением частоты принятия решений; тестировать приоритеты на фиксированных состояниях.
- W3.2 AI выбирает узлы для Tank/Scout/Ranger, защищает угрозу, атакует мешающего противника и не заполняет очередь NavMesh запросами каждую рамку.
- W3.3 Завершить реальный матч до 45 очков/180 с; проверить победу/поражение/ничью, паузу и завершение ввода после исхода.
- W3.4 Провести воспроизводимые серии локальных матчей с несколькими стратегиями и зафиксировать хотя бы один нетривиальный выбор. Баланс править данными, не добавляя новые подсистемы.

**Gate G3:** законченная короткая игра с действующим соперником; автоматический прогон и ручной тест Editor в доступной среде.

## W4 — VContainer: реальный composition root

- W4.1 Установка проверенной версии, manifest/lock/лицензия, компиляция и тесты.
- W4.2 `GameLifetimeScope` с одной реальной службой времени/состояния, тест её времени жизни.
- W4.3 Перевести зависимости match/AI/factory на явную регистрацию/внедрение. Избегать массового рефакторинга компонентов без причины.
- W4.4 Документировать объекты `Singleton/Scoped/Transient` именно этого проекта (могут использоваться не все); тест устранения зависимостей при Restart.

**Gate G4:** удаление/сломанная регистрация даёт обнаруживаемый сбой теста/запуска; сервис используется в настоящей игре, а не в sample-скрипте.

## W5 — Addressables + UniTask: создание и повторное появление

- W5.1 Установка/фиксация Addressables и UniTask **двумя отдельными** коммитами с проверкой compile.
- W5.2 Локальная группа Addressables, один адресуемый префаб роли, настройка content build, проверка загрузки в Editor и Player.
- W5.3 Provider/factory: загрузить → создать → зарегистрировать юнита → вернуть ownership; корректно уничтожить/release по смерти/рестарту.
- W5.4 UniTask запускает и ожидает спавн/загрузку с токеном отмены; обработка ошибок и поздних результатов.
- W5.5 Все шесть стартовых юнитов рождаются через единый путь и возрождаются через 10 игровых секунд; не должно быть созданных заранее параллельных юнитов.
- W5.6 Тесты cancellation, missing asset, duplicate spawn, failed spawns, restart during load, 10 restarts/leaks. Явный UI ошибки ресурса и Retry/Exit.

**Gate G5:** новая цепочка действительно работает от VContainer через UniTask к Addressables; в APK есть контент; ресурсы очищаются при завершении/рестарте.

## W6 — сенсорное управление, камера, HUD

**Gate G6:** управлять можно на телефоне без мыши; подтверждён экранный контроль на заявленных форматах (на устройстве, если доступно).

## W7 — полировка геймплея/обратная связь

- W7.1 Лаконичный читаемый визуальный язык узлов, команд, ролей и врагов; без сложных анимаций.
- W7.2 Минимальные SFX, mute; состояние захвата и повреждения видимо/слышимо.
- W7.3 Баланс партии: измерить время и результаты нескольких тактик, убрать очевидное авто-решение, если выявлено; документировать выводы, не добавлять вторую карту.
- W7.4 Исправления UI/приказов по ручным тестам; минимальный экран справки/инструкции по управлению.

**Gate G7:** человек, не читавший код, способен запустить игру, понять правила и завершить партию.

## W8 — надёжность, профилирование, APK

- W8.1 Прогнать все EditMode/PlayMode, статические проверки, тесты на 10 рестартов и ошибки ресурсов.
- W8.2 Собрать полноценный APK с локальным Addressables content; проверить clean checkout там, где возможно.
- W8.3 Проверка в Android по USB/ADB **если устройство реально подключено**, включая старт, завершение, паузу, перезапуск, касания, загрузки. Без ECS/DOTS/пула объектов при отсутствии необходимости.
- W8.5 Исправить настоящие проблемы; не переписывать работающие системы ради «более красивой архитектуры».

**Gate G8:** полный evidence manifest, Android build, известные ошибки/непроверенные случаи явно указаны.

## W9 — передача, документация, финальная приёмка

- W9.1 README с игровыми правилами, управлением, версиями, build/setup/test, архитектурной картой, скриншотами и ограничениями.
- W9.2 ADR ключевых решений и `THIRD_PARTY_NOTICES.md`, краткая карта «куда смотреть» для собеседования.
- W9.3 Обновить прежние docs, `IMPLEMENTATION_STATUS.md`, таблицу ID требований, номера/хеши коммитов; итоговый commit docs.
- W9.4 Финальная проверка `git status`, `git log`, ссылки документации, отсутствие лишних бинарников. Итоговый отчёт PASS/FAIL/BLOCKED с точными действиями для непройденных пунктов.

**Gate G9:** можно дать ссылку на репозиторий и объяснить, где код игровых механик/DI/async/assets/тестов. При отсутствии телефона нельзя писать «Android полностью протестирован».

## Если работа прервана

На любом milestone состояние должно быть безопасно сохранено локальными коммитами. `IMPLEMENTATION_STATUS.md` содержит последнюю пройденную задачу, фактический HEAD, чек тестов и следующий шаг. Агент может восстановить контекст и продолжить. Не заявлять фоновые/отложенные результаты без реального запуска новой сессии.
