# 03. Техническое задание: требования v1.0

Нормативные слова: **MUST** — необходимо для приёмки; **SHOULD** — желательно, но можно документированно перенести; **MAY** — необязательно. Конкретные правила — в `02_GAME_DESIGN.md`. Если реализация требует иных чисел, изменить данные и записать почему, не менять молча этот контракт.

## Обязательные отрицательные сценарии

- Два врага и союзник в узле (contest); пустой узел; смерть прямо при захвате; два узла приносят очки одновременно; ничья по времени.
- Нажатие по UI поверх юнита; swipe вместо tap; касание недоступной точки; скрытый геометрией юнит; отключённый NavMeshAgent.
- Атака через стену; потеря пути; частичный NavMesh путь; непроходимая цель не порождает сотни перерасчётов.
- Отмена UniTask при Restart/выходе; загрузка несуществующего Addressable; ошибка загрузки, повторный запрос, двойное освобождение.
- Смерть выбранного юнита; смерть/возрождение при Pause; перезапуск после Win/Loss/Draw; 10 последовательных рестартов.

## Definition of Done для требования

Сделано в реальном проекте и продемонстрировано, добавлен соответствующий тест/ручной чек, нет регрессии, понятен diff и есть проверенный коммит; обновлены статусы требований в `IMPLEMENTATION_STATUS.md`. Наличие кода без работающего запуска не означает готовность пользовательской фичи.
