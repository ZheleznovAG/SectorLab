# SectorLab — автономная реализация v1.0: комплект ТЗ и передачи агенту

Дата составления: 2026-10-11. Основа: пользовательский архив `SectorLab-for-ai-20261011-191247.zip` (снимок 19:12:48 +07:00).

**Комплект уже внесён в настоящий репозиторий.** Свежий аудит и следующий шаг
находятся в [IMPLEMENTATION_STATUS.md](docs/agent_execution/IMPLEMENTATION_STATUS.md),
логи — в [EVIDENCE_REPORT.md](docs/agent_execution/EVIDENCE_REPORT.md).
Раздел внедрения ниже описывает первоначальную передачу комплекта.

## Цель комплекта

Передать реализацию SectorLab агенту как **реальному исполнителю**, а не наставнику. Агент может менять проект, запускать проверки и создавать **локальные** Git-коммиты после проверки. Пользователь изучит реализацию позднее, используя историю коммитов и учебную карту. Не выдавать созданный ИИ код за собственную самостоятельную работу или коммерческий опыт.

## Инструкция по внедрению

1. Создать независимую копию/резервную точку текущего проекта. Не разворачивать архив поверх рабочей копии без проверки файлов. Архив с текущими незакоммиченными изменениями следует сохранить как источник, пока они не разобраны.
2. Скопировать **содержимое** данного комплекта в корень настоящего репозитория `[LOCAL_USER_HOME]\Projects\SectorLab` с предварительным сравнением `AGENTS.md` и `CLAUDE.md`. Это **предлагаемые новые редакции** двух файлов, они меняют прежний учебный режим на автономный. Сохранить предыдущие версии в Git как историю; не перезаписывать без просмотра.
3. Новые документы находятся в `docs/agent_execution/`. Существующие документы `docs/00_CONTEXT_STATUS.md`, `docs/03_ROADMAP.md`, `docs/06_GAME_DESIGN.md` и прочие — исторический контекст. При противоречиях **новое ТЗ действует для v1.0**, но агент должен сделать соответствующие осмысленные обновления исторических документов по ходу работы.
4. Дать агенту содержимое `AGENT_START_PROMPT.md` и доступ к реальному репозиторию и редактору Unity. Этот комплект **не реализует игру**, не меняет Git и не доказывает выполнение сборок.

## Карта документов

- `AGENTS.md` — полномочия, безопасность, порядок автономной работы.
- `CLAUDE.md` — краткие инструкции для Claude Code и других агентов, ссылающиеся на единое ТЗ.
- `AGENT_START_PROMPT.md` — стартовый запрос агенту.
- `docs/agent_execution/01_BASELINE_AUDIT.md` — что подтверждено по исходному архиву.
- `02_GAME_DESIGN.md` — утверждаемая в этом ТЗ ограниченная игровая концепция.
- `03_REQUIREMENTS.md` — функциональные и нефункциональные требования с ID.
- `04_ARCHITECTURE.md` — границы модулей, контрактов, времени жизни и ресурсов.
- `05_FRAMEWORKS.md` — работа VContainer, UniTask, Addressables.
- `06_DELIVERY_PLAN.md` — порядок рабочих пакетов и зависимости.
- `07_TEST_PLAN.md` — матрица автоматизированных и ручных проверок.
- `08_GIT_AND_AUTOMATION.md` — подлинная история Git, интеграция, ограничения агента.
- `09_ACCEPTANCE.md` — доказательства готовности и итоговый handoff.
- `10_RISKS_AND_DECISIONS.md` — риски, решения, границы автономии.
- `11_STUDY_MAP.md` — что изучать после работы агента и как объяснять код.
- `12_RELEASE_CHECKLIST.md` — независимый список приёмки продукта.
- `WORK_ITEMS.csv` — стартовый реестр задач с зависимостями и проверками.

## Приоритет источников

Текущее дерево файлов и исполняемые тесты > проверяемое состояние Git > этот контракт v1.0 (для **целевого поведения**) > прошлые планы `docs/` > предположения. Изменения требований агента без записи в журнале решений недопустимы.

## Короткое определение v1.0

**SectorLab: Relay Skirmish** — офлайновая однопользовательская мобильная тактика с видом сверху; три роли юнитов, короткая партия за энергетические узлы, простой противник, счёт, перезапуск, интерфейс и удобное сенсорное управление. Целевая платформа Android, разработка в Unity 6000.6.4f1. Должна быть **реальная**, воспроизводимая демонстрация трёх технологий: VContainer, UniTask, Addressables.

Примечание: оригинальная документация не утверждала этот геймдизайн. Здесь он принят **как проектное предложение/контракт для автономной реализации**, потому что иначе нельзя поручить агенту закончить игру. Владелец вправе изменить концепцию до запуска исполнения.
