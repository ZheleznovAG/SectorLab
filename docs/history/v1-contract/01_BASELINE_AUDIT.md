## Что в коде требует внимания при переходе на v1.0

1. `BattleController.Update` считает живых юнитов и заканчивает матч уничтожением команды. Для новой цели по очкам будет нужна переработка правил завершения, а не добавление параллельного несовместимого контроллера.
2. `Unit.All` — статический реестр через `OnEnable/OnDisable`. Удобно для маленькой арены, но при повторном появлении, повторном запуске и асинхронной загрузке требуется доказать отсутствие «старых» ссылок/дубликатов и безопасную очистку. **Не запрещено использовать до измеримой проблемы**.
3. `UnitCommander` опрашивает `Pointer.current`, имеет допуск касания и прямую выдачу приказов. Жесты камеры, исключение UI-касаний и выбор узлов должны быть реализованы без ложных приказов.
4. `Health` не умеет лечить — нужна отдельная проверенная операция `Heal`, если применяется ремонтный узел.
5. `UnitAttack` и `UnitMovement` имеют незакоммиченные улучшения проверки препятствий, частичного пути, ограничения повторных запросов и семантики отклонённого приказа. Их надо ревьюить и закрыть **до** расширения игрового процесса.
6. Существующие префабы основаны на Unit/Enemy + вариантах роли, ScriptableObject чисел. Это хорошая основа для Addressables; не плодить копии всех юнитов.
7. UI использует старый `UnityEngine.UI.Text`, камера статична, арена тесная. При новой цели нужен UX обзор, пригодный для телефона.
8. В текущих `AGENTS.md`/`CLAUDE.md` явно запрещена автономная работа; их новая редакция входит в данный комплект и требует осознанного внедрения.

Здесь выполнялся статический анализ ZIP, файлов и локальной истории Git; Unity Editor, Android APK и тесты **не запускались**. Для Git со включённым LFS в окружении проверки не было установленного `git-lfs`; вывод `git status` получен с временно отключённым процессным фильтром. Это ограничение локальной проверки, а не подтверждение неисправности репозитория.
