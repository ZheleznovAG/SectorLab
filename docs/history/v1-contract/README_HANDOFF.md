# SectorLab — передача разработки агенту

> Исторический комплект ручного режима R0–R5. С 2026-10-11 текущие полномочия
> и целевая v1.0 определяются [README_START.md](README_START.md) и [AGENTS.md](AGENTS.md).
> Подтверждённое состояние: [IMPLEMENTATION_STATUS.md](docs/agent_execution/IMPLEMENTATION_STATUS.md).

**Версия документации:** 1.0 · **Дата фиксации контекста:** 10.10.2026

Этот комплект предназначен для продолжения разработки Unity-проекта **SectorLab** с ИИ-агентом в режиме «разработчик пишет руками, агент помогает понять и проверить». Документы определяют **намерение и способ работы**, но не утверждают, что код или сцена уже существуют.

## С чего начинать

1. Агент читает [`AGENTS.md`](AGENTS.md) — обязательные правила работы.
2. Затем [`docs/00_CONTEXT_STATUS.md`](docs/00_CONTEXT_STATUS.md) — факты, гипотезы, неизвестное и проверка репозитория.
3. Затем [`docs/01_VISION.md`](docs/01_VISION.md), [`docs/02_WORKFLOW.md`](docs/02_WORKFLOW.md) и [`docs/03_ROADMAP.md`](docs/03_ROADMAP.md).
4. Перед изменением исходников агент **проверяет фактическое состояние проекта**, не выводит готовность R0 из существования архива или предыдущей беседы.
5. Выполняется **одна микроитерация за раз**, с проверкой и отдельным осмысленным коммитом после подтверждения пользователя.

## Как применять пакет

Это **только Markdown-документация**: здесь нет скриптов, меняющих код, Unity-сцены или настройки. Распакуйте в отдельную папку, прочитайте файлы, затем перенесите нужные документы в корень Unity-репозитория. Если там уже есть `AGENTS.md` или документы с аналогичными именами — **сначала объедините правила вручную**, не затирайте существующие.

Рекомендуемое расположение проекта из предыдущего планирования: `[LOCAL_USER_HOME]\Projects\SectorLab`; реальный путь должен подтвердить пользователь или локальный агент.

## Главное правило

> Сначала маленькая реальная задача и самостоятельное понимание; только потом расширение архитектуры и библиотеки. Нельзя заменять обучение большой автоматически сгенерированной реализацией.
