# Дорожная карта: от пустой сцены до первой партии

**Примечание:** это план, а не отметки завершения. Подтверждать сделанное по репозиторию/у пользователя. Номера служат навигацией, не жёстким контрактом.

## R0 — техническая основа

**Результат:** проект открывается, сцена понятна, полe видно, путь к Android проверен по возможности.

| ID | Минимальный результат | Рекомендуемый коммит |
| --- | --- | --- |
| R0.0 | Новый Unity-проект `SectorLab` с URP открывается без ошибок | `chore: initialize Unity project` |
| R0.1 | Git, Unity `.gitignore`, первая сохранённая сцена, каталоги | `chore: organize Unity project` |
| R0.2 | Одна поверхность — `Ground`, координаты/масштаб понятны | `feat: add ground plane` |
| R0.3 | Камера показывает арену сверху, выбран тип проекции | `feat: configure top-down camera` |
| R0.4 | Освещение позволяет различать объекты | `style: configure scene lighting` |
| R0.5 | Несколько простых блоков формируют тестовую арену | `feat: add arena blockout` |
| R0.6 | Проверен горизонтальный экран и читаемость объектов | `chore: configure mobile presentation` |
| R0.7 | Первая Android-сборка проверена на устройстве, если доступно | `build: validate Android baseline` |
| R0.8 | README с запуском, ограничениями и известными проблемами | `docs: document R0 baseline` |

Не делать R0 через автоматический генератор сцены, пока пользователь явно не изменит предпочтение. При наличии ранее сгенерированной сцены сначала выяснить, нужно ли её сохранить как reference, а не уничтожать.

## R1 — первый управляемый юнит

**Результат:** игрок выбирает условного робота и может направить его к точке на поверхности.

| ID | Результат | Что изучаем |
| --- | --- | --- |
| R1.0 | Один примитивный юнит | GameObject, Transform |
| R1.1 | Минимальный `UnitMovement` | MonoBehaviour и компоненты |
| R1.2 | Движение к заранее заданной позиции | `Vector3`, `Update`, `Time.deltaTime` |
| R1.3 | Остановка у точки, без перескока | Расстояние, `MoveTowards`, точность |
| R1.4 | Получаем точку поверхности из нажатия | Screen/World, Raycast |
| R1.5 | Нажатие на землю отдаёт команду двигаться | Границы ввода и движения |
| R1.6 | Игрок выбирает юнита | Объекты выбора, состояние |
| R1.7 | Выделение/точка назначения видны | Визуальная обратная связь |
| R1.8 | Проверен сенсорный сценарий | Input System, UI vs world input |
| R1.9 | Юнит пригоден для повторного использования | Prefab |

**Не добавлять:** обход препятствий, формации, многопользовательский режим, сложный ИИ.

## R2 — первое взаимодействие

Маленькие части: враг-заглушка → здоровье и урон → простая атака → реакция на уничтожение → визуальная индикация → тесты устойчивых игровых правил.

**Результат:** игрок может повлиять на другой игровой объект.

## R3 — короткая законченная партия

Минимальный цикл: 2–3 своих юнита, простое противодействие, ясная цель, победа/поражение, кнопка перезапуска. Цель — партия длительностью порядка 1–3 минут, а не полноценная RTS.

**Результат:** прототип можно сыграть от начала до конца.

## R4 — одна интересная тактическая механика

Экспериментировать с **одной** гипотезой за раз: удержание точек, разные возможности юнитов, защита оборудования, маршруты, укрытия и т.д. Оценка: приводит ли механика к реальному выбору? Ненужное удаляем.

## R5 — маленькая завершённая демонстрация

Читаемый UI, обратная связь, звук по необходимости, несколько сценариев, тесты, простая документация, профилирование по реальным проблемам, минимальное удобство мобильного ввода.

## Вехи технологий

- Input System — при работе над касаниями/мышью.
- ScriptableObject — при необходимости вариативных конфигураций.
- Unit Tests — для проверяемых правил и изменений поведения.
- VContainer/UniTask/Addressables — после появления реальной потребности или в **явно отдельном** учебном spike.
- Object Pool и Profiler — при заметной/измеряемой необходимости.

Переход к следующему пункту не автоматический: сначала критерии готовности предыдущего.
