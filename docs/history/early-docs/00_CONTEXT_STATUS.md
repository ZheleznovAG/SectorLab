## Что известно из обсуждения

- Рабочее название Unity-проекта — **SectorLab**. Прежнее имя MicroTactics снято с актуального плана.
- Назначение: небольшой мобильный тактический/стратегический прототип, который можно понять, развить и показать при отклике на Unity-вакансию Gear Games.
- Важнее не скоростная генерация кода, а **осознанная самостоятельная разработка малыми шагами**.
- Направления игры обсуждались: захват точек, отряд дронов, конвой, заражённая станция, сбор ресурсов и др. **Жанр/основная механика не утверждены.**
- Целевые технологии для изучения: C#, Unity Input System, Prefabs, ScriptableObject, Unit Tests, UniTask, VContainer, Addressables, профилирование. Input System, префабы, ScriptableObject, тесты и профилирование уже используются.

## Проверка и исправления после ревью (2026-10-11, ещё без коммита)

По явной просьбе пользователя агент применил последовательные исправления и запустил проверки:

- Геометрия слоя Default блокирует атаки: `Physics.Linecast` между центрами юнитов игнорирует триггеры. Если цель закрыта, атакующий продолжает сближение по NavMesh. Проверены отсутствие урона через блок, возобновление атаки после удаления блока и обход блока с последующим попаданием.
- `MoveTo` возвращает, принят ли запрос `SetDestination`. Отключённый агент, потеря NavMesh и недействительный путь сбрасывают `IsMoving`. Маркер не показывается при отказе. Частичный путь разрешён до доступного конца; достижение самого запрошенного назначения не гарантируется. Проверка частичного пути проходила и до исправления.
- Допуск касания выбирает только юнита, чей коллайдер первым виден лучу от камеры к его экранному центру. Проверены видимый и закрытый блоком юниты. Частичная видимость при закрытом центре пока не учитывается.
- В настоящей `Main` приказы через `HandleTap` выбрали всех трёх своих юнитов и направили их на EnemyScout. После гибели Scout и Tank дополнительный приказ отправил оставшегося Ranger на EnemyRanger; результат — поражение, у EnemyRanger осталось 14 HP. Панель поражения, отключение управления и обработчик кнопки Restart проверены; после перезапуска — `InProgress`, 3 vs 3, управление включено. Это один скриптовый прогон, не ручная игра и не повторение прежнего эксперимента с балансом.
- Через ADB проверен список устройств: подключённых устройств нет. Предыдущий `SectorLab.apk` не заменялся. Временная запись Input System в `preloadedAssets` удалена после сборки.

Предыдущие выводы о победных планах относятся к коду до блокировки атак препятствиями; их нельзя автоматически переносить на текущую версию.

### Уточнения после повторного аудита (2026-10-11, без новых коммитов)

- Усилен тест частичного пути: проверяются принятие запроса, `hasPath`, `PathPartial`, ненулевая длина доступного участка, реальное перемещение больше 0,5 м и остановка до назначения. Немедленный отказ теперь не может пройти этот тест.
- В контролируемом тесте с непроходимой стеной и принудительным завершением движения старая атака запустила 71 новую попытку за 0,3 с. Автоматические запросы пути ограничены интервалом 0,5 с. Новая явная цель сбрасывает ожидание; недостижимая цель сохраняется, чтобы преследование возобновилось, когда путь откроется. Проверены ограничение повторов и попадание после удаления стены и перепекания NavMesh.
- Выбранное правило управления: немедленно отклонённый приказ «идти» сохраняет прежнюю цель атаки и не показывает маркер; принятый приказ отменяет атаку. Частичный путь остаётся принятым запросом. Проверка прежней цели сначала падала, после изменения порядка вызовов прошла.
- Итог: 9/9 EditMode и 38/38 PlayMode, без пропущенных тестов. Сравнение файлов в ZIP 14:34 и 16:24 по SHA-256 показало 11 изменённых файлов проекта; изображения между архивами идентичны. APK из прошлого цикла и архивы не заменены.
