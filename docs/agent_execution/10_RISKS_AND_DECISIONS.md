## Риски и планы смягчения

| Риск | Вероятность / ущерб | Мера |
| --- | --- | --- |
| Архив отражает неактуальную рабочую копию | Высокая / высокая | Сверка SHA/HEAD/status до любых правок |
| Старые незакоммиченные багфиксы теряются | Средняя / высокая | Резервная копия, review patch, отдельные коммиты |
| Отсутствие Git LFS даёт ложные изменения PNG | Средняя / средняя | `git lfs status`, сравнение реальных blob, не коммитить мусор |
| Проблемы совместимости Unity 6000.6/версий UPM | Средняя / высокая | Пин версии, одна установка = один compile/test commit; не апгрейдить весь Editor |
| Addressables handle высвобождается дважды или поздно после отмены | Средняя / высокая | Явный ownership, cancel/load/error tests, десять restart |
| DI-контейнер перехватил слишком много ответственности | Средняя / средняя | Composition root, 1 scope матча, минимум сервисов |
| AI строит слишком много путей / зацикливается | Средняя / средняя | Интеграция существующего throttle, периодическое decision, profiler |
| Узлы не добавляют тактический интерес | Средняя / высокая | Скриптовые планы + живой плейтест, баланс положений/ролей до новых механик |
| Сенсорные жесты конфликтуют с приказами | Высокая / средняя | Tap/drag threshold, UI raycast blocking, virtual touch/Android |
| Недоступен Android для проверки | Высокая / высокая для публикации ||
| AI создаст «идеальную» фальшивую Git историю | Средняя / высокая | Реальные малые commits после тестов, запрет rebase/force/backdating |
| Внешние арт-ресурсы нарушают лицензии | Низкая / высокая | Unity primitives/свои материалы, notices для библиотек/asset |
| MVP разрастается в полный RTS | Высокая / высокая | Явный Out of Scope, milestone gates, без новой механики до завершения G9 |

## Открытые вопросы, которые агент разрешает самостоятельно в узких рамках

- Техническая реализация `RelayPoint` (компонент vs простой адаптер) — документировать результат тестов.
- Конкретный совместимый tag VContainer/UniTask и package Addressables — использовать официальные версии, зафиксировать сведения.
- Нужен ли отдельный Menu/Bootstrap Scene или достаточно Main + начального overlay — выбрать простейший работающий способ с чистым lifecycle, не раздувать сцены.
- Способ фиксации step/tick для capture/score/respawn — сохранить независимость от FPS, покрыть тестами.
- Как отобразить recharge/respawn и статус узла при тесном экране — оптимизировать под читаемость, зафиксировать скриншоты.

## Где остановиться для решения владельца

Если требуется сменить жанр/платформу, купить ассеты, использовать закрытые API/сервисы, публиковать код/билд на удалённом ресурсе, переписать историю Git или удалить существенную часть работающего проекта, агент не делает это автоматически. В остальных случаях принимает небольшие технические решения и записывает их в ADR, не запрашивая подтверждение каждого класса.
