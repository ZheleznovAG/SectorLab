# 02. GDD / дизайн SectorLab: Relay Skirmish v1.0

## Статус идеи

**Проектное предложение, выбранное для автономной версии v1.0**, не утверждавшееся в старых документах. Цель — закрыть неопределённость и избежать бесконечного выбора жанра агентом. SectorLab остаётся названием репозитория; рабочее название игрового режима: **Relay Skirmish / Битва за узлы**.

## Фантазия игрока и игровой цикл

Игрок — командир трёх специализированных роботов на маленькой промышленной арене. Две станции питания дают очки контроля; третья станция восстанавливает повреждённых бойцов. Враги претендуют на те же объекты. Нужно перемещать разных бойцов, отвлекать противника, защищать узлы и сохранять темп получения очков.

**Цикл:** оценить карту → выбрать робота → приказать двигаться/атаковать/занять узел → получить явную обратную связь → потерять/сохранить контроль → перестроить план. Длительность партии — до 3 минут; партия завершается раньше при достижении лимита очков.

## Арена, состав и роли

- Одна компактная симметричная арена (начальную `Main.unity` адаптировать без потери существующих данных). Полосы проходимости проверены NavMesh, узлы не должны быть блокированы геометрией. Разрешены простые low-poly примитивы с аккуратной цветовой схемой.
- У игрока и противника по три роли: **Tank** (живучесть/удержание), **Scout** (быстрый перехват), **Ranger** (дистанционная атака). Начальные числа берутся из текущих `UnitStats`, а не дублируются константами в новых классах; баланс допускается по результатам тестов.
- На экране максимум по одному активному юниту каждой роли на сторону (3 vs 3). При смерти роль становится недоступна на **10 игровых секунд**, потом в своей точке появления появляется снова с полным здоровьем; если место занято, спавн переносится на ближайшую безопасную точку NavMesh либо корректно откладывается. Таймеры замораживаются на паузе и отменяются при перезапуске.
- Не вводить постройки, дерево технологий, карты, классы/навыки по 10 вариантов, мультиплеер, прокачку вне боя или экономику.

## Узлы

- **A, B — очковые узлы.** **C — ремонтный узел.** Все стартуют нейтральными. Конфигурация узла хранится в данных, а не в разветвлённых `if` по имени.
- Радиус захвата по горизонтали — базово 1,5 м, уточняемый для читаемости. Захват одной командой без противника идёт **5 секунд** от нейтрали до полного владения. Большее количество бойцов не ускоряет захват в v1.0.
- Состояние прогресса от −1 (полностью принадлежит врагу) до +1 (полностью принадлежит игроку), 0 — нейтрально; без присутствующих бойцов прогресс сохраняется. Сдвиг к своей стороне идёт со скоростью 1/5 единиц за секунду. **Важный эффект: переход полностью контролируемой врагом точки в свою занимает до 10 секунд** (сначала нейтрализация, потом захват). При присутствии обеих команд прогресс заморожен, статус `Contested`.
- Владелец на HUD считается игроком/врагом только при полностью достигнутых +1/−1. **Нормативное правило:** при начавшейся нейтрализации, оспаривании или неполном владении функция узла не действует. Это устраняет неоднозначность: начисление только при полном прогрессе, отсутствии врага в радиусе и хотя бы одном своём бойце на узле; после ухода своей команды полностью захваченный узел продолжает приносить очки, если противника нет. Для ремонта присутствие своих бойцов в радиусе обязательно.
- Для A/B: полностью контролируемый игроком узел без вражеского бойца внутри радиуса приносит **1 очко/с** соответствующей стороне. Оба узла вместе — 2 очка/с. Начисление по `deltaTime`, без зависимости от числа кадров. При оспаривании очки узла приостанавливаются.
- Для C: полностью контролируемый ремонтный узел лечит союзников **по 6 HP/с**, находящихся в радиусе, если врага в нём нет. Лечение не действует на мёртвых, не превышает Max; точно рассчитать дробные доли/тик для целочисленной `Health` (фиксированный тик с накопителем или дробный буфер). Старые значения HP не подменять.

## Победа и поражение

- **Порог — 45 очков.** Первый достигший порога побеждает. При одновременном достижении в одном симуляционном тике — ничья.
- **Лимит — 180 игровых секунд.** По таймауту выигрывает сторона с большим количеством очков; при равенстве ничья (`Draw`). Уничтожение всей текущей команды **не завершает матч**: действует повторное появление.
- Если игра на паузе, счёт, захват, восстановление, AI и таймеры не продвигаются. По завершении матча не действуют команды и не создаются новые юниты; итоговый экран содержит счёт и `Restart`.
- После `Restart` состояние возвращается к нейтральным узлам, нулевым очкам, полным составам, исходной геометрии и начальным данным без дублирования объектов/подписок/Addressables handles.

## ИИ соперника (понятный, честный)

- AI принимает решения периодически, примерно 1 раз/с, без кадрового перебора сложного дерева поведения.
- Приоритет: предотвратить прямой захват своего очкового узла, захватить доступный нейтральный/вражеский очковый узел, обеспечить ремонт сильно повреждённому бойцу (если C под контролем), атаковать мешающую цель.
- Одни и те же механизмы команд/навигации/атаки для игрока и ИИ. Нельзя телепортировать вражеских бойцов или давать скрытый бонус к здоровью.
- Периодическое переназначение ролей не должно спамить `SetDestination`. При равных целях — стабильный порядок/seed для воспроизводимых тестов. ИИ не обязан быть «умным»: он должен **составлять конкуренцию за узлы**.

## Управление/UX

- В редакторе: ЛКМ выбрать юнита/цель/узел, клик на землю — движение; мышиный drag — панорамирование (не выдаёт приказ), колёсико — масштаб.
- На телефоне: короткое касание = выбор/команда; один палец с перетаскиванием = панорамирование; два пальца = масштаб; нажатия на UI не попадают в мир. Установить порог смещения для различия tap/drag; проверять DPI fallback и `Screen.safeArea`.
- Выбранный юнит подсвечен, приказ показан маркером/линией, цель доступна для чтения. При касании узла выбранный робот идёт к доступной точке внутри радиуса захвата.
- HUD: очки, оставшееся время, принадлежность A/B/C, индикатор захвата/оспаривания, подсветка выбранной роли и её HP, пауза/возобновить, результат и перезапуск.
- Мини-обучение в 2–3 коротких подсказках при первом запуске; можно пропустить. Звук (выстрел, захват, результат) с общей кнопкой отключения, без обязательного сложного аудиодвижка.

## Почему это интересно (проверяемая гипотеза)

Танк может удерживать занятый узел, разведчик переключается между A и B, стрелок прикрывает подход. Ремонтный C соблазняет увести бойца из зоны заработка. Разделение сил должно чаще быть выгоднее «всех в одну точку», но **не обязано**: проверять минимум два-три разных выигрышных плана в плейтестах; если тактики не возникает, настроить позиции/характеристики, а не плодить новые системы.

## Не входит в v1.0

Здания, конвейеры, крафт, производство, инвентарь, ресурсная экономика, сетевой мультиплеер, облачная загрузка контента, донат, реклама, управление 30 юнитами, уровень из нескольких карт, процедурная генерация, полноценные 3D-анимации. Всё это — отдельные возможные версии после завершённого MVP.
