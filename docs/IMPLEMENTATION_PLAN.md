## Порядок и проверки

1. Регрессии сначала обнаруживают дефект, затем проходят с исправлением.
2. Представление читает общую модель; клиент не запускает симуляцию ради обновления UI.
3. Сеть получает один полный снимок с раздельными номером снимка и игровым тиком,
   поколением матча и состоянием всех слотов. Старые/повреждённые сообщения не меняют модель.
4. Поколение бойца разделяет воплощения после респауна; звуки и интерполяция сбрасывают историю.
5. Причины паузы не снимают друг друга; клиентские окна управляют только локальным вводом.
6. Реестр матча и команды ИИ меняются после исправления сетевой корректности.
7. Для каждого законченного изменения: затронутые тесты, полный набор и `sl.py check`.
   Исторические evidence не перезаписываются. При изменении входов — новый прогон.
8. Итог: проверка двух процессов, версия APK/CHANGELOG, актуальные STATUS и ADR.

Сетевые сервисы, новые карты/способности, смена стека и полная изоляция нескольких
симуляций в одном процессе в этот план не входят.
