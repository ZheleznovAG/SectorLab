# Геймдизайн: гипотезы вместо преждевременного выбора жанра

## Пока не решено

Вектор — небольшая мобильная тактическая игра с видом сверху. Обсуждались: управление отрядом, захват точек, защита реактора, заражённая станция, конвой, сборщик ресурсов, робот с помощниками, микротактика. **Ничто не утверждено как окончательная концепция.**

## Возможные направления

| Идея | Возможный интерес | Основной риск |
| --- | --- | --- |
| Захват контрольных точек | Конфликт за территорию и распределение сил | Без интересного ИИ превращается в ожидание на кружках |
| Тактический отряд | Выбор юнита, позиционирование, команды | Сложность ИИ, навигации и мобильного управления |
| Защита реактора | Приоритет угроз, перестановка обороны | Слишком пассивный игровой процесс |
| Заражённая станция | Тактика помещений, двери, опасности | Легко разрастись в контент и системы |
| Сборщик/конвой | Риск, маршрут, ресурсы, эвакуация | Требует продуманного повторяемого цикла |

## Основной игровой цикл — будущая гипотеза

Оценить ситуацию → отдать приказ → получить обратную связь → увидеть последствия → принять следующий выбор.

Для R1 мы проверяем **управление**, а не геймдизайн целиком. Для R3 уже нужен завершённый цикл партии. В R4 проверяем одну особенность, которая заставляет выбирать между несколькими действиями.

## Mechanics / Dynamics / Aesthetics (MDA)

- **Mechanics (правила):** точка захватывается за время, скорость юнитов различается.
- **Dynamics (возникающее поведение):** игрок разделяет отряд, пытается обходить, жертвует одним участком ради другого.
- **Aesthetics (переживания):** ощущение тактического решения, напряжение, контроль ситуации.

Из-за того, что реализована механика, не следует, что игроку интересно. Проверяем в игре.

## Шаблон маленькой игровой гипотезы

- Предположение: «Если у двух дронов разная скорость, игроку придётся распределять задачи».
- Эксперимент: два дрона, две цели, одна короткая арена.
- Наблюдения: возникают ли как минимум два разумных решения? не существует ли всегда одного очевидного?
- Вывод: сохранить, изменить или удалить.

## Мобильный контекст

Учитывать читаемость объектов и выделения на небольшом экране, попадание пальцем, отличие касания от перетаскивания, конкуренцию ввода мира с UI. Прототипировать на телефоне по возможности рано.
