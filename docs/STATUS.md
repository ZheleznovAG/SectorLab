## Дальше (по приоритету)

1. **Нужен человек с телефоном.** Установить APK D3-docs (`python Tools/sl.py install-android`), сыграть партию с ИИ и проверить B1–B4. Затем сетевую партию: ПК-хост
   (Editor: «Сеть» → «Создать игру») против телефона («Подключиться», IP хоста) или два телефона.
2. Клиенту не видно выстрелов и таймера возвращения бойцов: снимок несёт только позиции и HP.
   Добавить в `UnitsSnapshot` событие выстрела и оставшееся время респауна по слотам.
3. Интерполяция позиций на клиенте: снимки 10 Гц, сейчас юниты-прокси прыгают.
4. Игра не в одной Wi-Fi: relay (Unity Gaming Services Relay) или другой посредник. Решение — отдельным ADR.
5. Долг из аудита: `Unit.All` — статический реестр (мешает двум матчам в одном процессе);
   ИИ хоста управляет юнитами напрямую, а не через `MatchCommands`.
6. CI: владельцу добавить секреты `UNITY_LICENSE`, `UNITY_EMAIL`, `UNITY_PASSWORD`, запустить workflow
   вручную, при успехе включить триггеры `push`/`pull_request`.
7. Решить, нужна ли v1.1 с механическими различиями ролей (например, способность Scout).

## Известные ограничения

- Одна карта, 3×3, без прогрессии и экономики. Графика — примитивы Unity.
- Сеть: один соперник, только IPv4 в одной локальной сети, без шифрования и аутентификации.
  Хост проверяет каждый приказ (`MatchCommands`), но канал не защищён.
- Сборка Android перезаписывает `preloadedAssets` в `ProjectSettings.asset`; `sl.py build-android`
  предупреждает, вернуть: `git checkout -- ProjectSettings/ProjectSettings.asset`.
- Сборка Windows-плеера требует явной сборки Addressables (меню **SectorLab → Build local unit content**),
  иначе в плеере нет бандлов юнитов.
