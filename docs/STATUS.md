## Проверки

Полный текущий набор Editor — **260 тестов PASS**. Дополнительно прошли адресные фикстуры:
бой 21, клиентское представление 6, сетевое меню 3 и сетевой матч 4. Python-регрессии tooling — 10/10.
Результаты сборок и двухпроцессной UDP-приёмки — в [отчёте исправлений](review/REMEDIATION_2026-10-27.md).
Windows QA и Android собраны без ошибок, содержимое сверено с платформенными manifest;
два Windows-процесса по UDP — [16/16 PASS](evidence/network-review-fixes-v130.json).
Настройка обучения сохраняется при [отсутствующем ключе, 0 и 1](evidence/review-fixes-preferences.json).

Проверено автоматически: матч/ИИ/узлы/возрождение/повтор, загрузка/отмена ресурсов, жесты и UI,
причины паузы, кодеки, отказы сетевых ролей, клиентские прокси и линии выстрелов, бюджеты GC.
Это не заменяет живой игровой прогон на Android и проверку доступности интерфейса человеком.

Быстрые проверки CI запускаются на push/PR: Python 3.9 и 3.14 на Windows/Linux, гигиена и Gitleaks.
[Первый запуск](https://github.com/ZheleznovAG/SectorLab/actions/runs/40295350670) прошёл на прежней базе.
Unity/GameCI настроен на push в main, PR и ручной запуск; проверены
синтаксис workflow и наличие образа Unity 6000.6.4f1. Секреты `UNITY_LICENSE`, `UNITY_EMAIL`,
`UNITY_PASSWORD` отсутствуют (проверено 27.10); облачный прогон и обязательность gate ещё не подтверждены.
Workflow явно сообщает об отсутствии лицензии; после push ожидается отказ license preflight,
пока секреты не настроены. Это не дефект игрового кода и не успешный облачный прогон Unity.

Эмулятор Android не годится для проверки: ARM64-сборка Unity падает в нём с SIGILL ещё до сцены
([разбор](history/v1-contract/ANDROID_EMULATOR.md)). Проверка — только на телефоне, сейчас устройство недоступно.

## На чём остановились (27.10.2026)

После комплексного ревью владелец разрешил выполнить весь план исправлений. Исправлены:

- **R-07/R-06:** Android и Windows явно выбирают target и собирают контент до Player build;
  manifest и артефакт сравниваются по путям, размерам и SHA-256. Каталог без бандлов отклоняется.
  Публичная настройка layout убирает диалог первого content build; readiness polling ждёт domain reload.
- **R-01:** ошибка смены сетевой роли пересоздаёт Offline-матч с ИИ и сохраняет понятное сообщение.
- **R-02:** клиент рисует авторитетные линии новых выстрелов, не запускает собственный бой и не
  повторяет историю при подключении, дубликате, смерти, респауне или новом матче. Протокол **v3**,
  несовместим с v1/v2; обоим участникам нужна версия 1.3.0.
- **R-04/R-05:** сетевая фикстура восстанавливает настройку обучения; повторное имя проверки
  отклоняется до Unity и не перезаписывает JSON/CSV.
- **A-01:** все готовые выстрелы тика собираются до применения урона. Возможна взаимная гибель;
  проверка обеих последовательностей регистрации проходит. Полные тактические матчи проходят.
- **R-03:** подготовлены PR/push Unity workflow, фильтр собственных тестовых сборок и явный preflight;
  завершение зависит от внешней лицензии и первого реального облачного прогона.

Новые решения: [ADR-021](adr/021-explicit-platform-content-and-artifact-validation.md),
[ADR-022](adr/022-simultaneous-ready-shots.md), [ADR-023](adr/023-replicated-shot-endpoints.md).
Обновлены правила и архитектура без новых runtime-сервисов и обновлений зависимостей.
Прежние отчёты не переписаны. В частности, прежнее утверждение о полноте Android 1.2.0
было неверно: присутствия `assets/aa/` оказалось недостаточно.

Исправления разделены на небольшие коммиты; результаты тестов и сборок сохранены с исходными
`sourceHead` и хешами входов, без подмены их на последующие commit SHA. Владелец подтвердил
коммиты и отправку в `origin/main`. Архив для анализа скопирован в Downloads; в Git он не включён.

## Известные ограничения

- Одна карта, 3×3, без прогрессии и экономики. Графика — примитивы Unity.
- Сеть: один соперник, только IPv4 в одной локальной сети, без шифрования и аутентификации.
  Хост проверяет каждый приказ (`MatchCommands`), но канал не защищён.
- Сборка Android может менять `preloadedAssets` в `ProjectSettings.asset`. Проверять diff и
  возвращать только служебную правку, сохраняя намеренные настройки/версию.
- Для ручной Player build в обход `sl.py` явная сборка и проверка контента остаются обязанностью
  разработчика. QA-команды включаются только с `--qa` и не должны попадать в обычный APK.
- Поведение на физическом Android, реальном Wi-Fi с потерями и облачном Unity runner в этой
  сессии не подтверждено. Производительность Windows/Editor не выдаётся за мобильную.
