## Проверки

Полный текущий набор Editor — **263 теста PASS** (`audit-2026-10-27-full`, входы совпадают с деревом). Дополнительно прошли адресные фикстуры:
бой 21, клиентское представление 6, сетевое меню 3 и сетевой матч 4. Python-регрессии tooling — 12/12.
Результаты сборок и двухпроцессной UDP-приёмки — в [отчёте исправлений](review/REMEDIATION_2026-10-27.md).
Windows QA и Android собраны без ошибок, содержимое сверено с платформенными manifest;
два Windows-процесса по UDP — [16/16 PASS](evidence/network-review-fixes-v130.json).
Настройка обучения сохраняется при [отсутствующем ключе, 0 и 1](evidence/review-fixes-preferences.json).

Проверено автоматически: матч/ИИ/узлы/возрождение/повтор, загрузка/отмена ресурсов, жесты и UI,
причины паузы, кодеки, отказы сетевых ролей, клиентские прокси и линии выстрелов, бюджеты GC.
Это не заменяет живой игровой прогон на Android и проверку доступности интерфейса человеком.

Быстрые проверки CI запускаются на push/PR: Python 3.9 и 3.14 на Windows/Linux, гигиена и Gitleaks.
[Первый запуск](https://github.com/ZheleznovAG/SectorLab/actions/runs/40295350670) прошёл на прежней базе.
Unity-тесты и сборки выполняются локально через `Tools/sl.py` в установленном Editor.
По решению владельца сервисы Unity Cloud и новый облачный CI не подключаются;
[порядок проверок](CI_READINESS.md), [ADR-024](adr/024-local-unity-validation.md).
GameCI оставлен только для ручного `workflow_dispatch`: push/PR не требует облачных Unity secrets.
Обязательного автоматического Unity PR-gate нет; R-03 в этой части отложен по решению владельца.
Прежние облачные попытки остановились до Unity-тестов на license preflight;
локальные 263 PASS остаются локальным результатом.

Эмулятор Android не годится для проверки: ARM64-сборка Unity падает в нём с SIGILL ещё до сцены
([разбор](history/v1-contract/ANDROID_EMULATOR.md)). Проверка — только на телефоне, сейчас устройство недоступно.

## На чём остановились (27.10.2026)

Проведён [комплексный аудит](audit/2026-10-27-complex-audit.md) базы `54ce798`: дефектов P1/P2 нет.
По просьбе владельца исправлены все шесть мелких находок:

- **C-01:** хост без соперника ждёт без таймаута и показывает IP; сообщение о несогласовании —
  только при подключённом сопернике. Клиент после потери хоста не получает ложной ошибки версии.
- **C-02:** у сетевого клиента обучение не открывается само поверх идущего у хоста боя.
- **C-03…C-06:** target SDK Android явно 36; actions закреплены по SHA; удалён `com.unity.collab-proxy`;
  отчёт исправлений получил ссылку на ADR-024.

Адресные и полный прогон прошли (88 + 175). Затем версия поднята до **1.3.1/code 5** (два разных APK
не должны носить одну версию) и выполнена приёмка сборок:

- Windows QA [собран](evidence/windows-build-v1.3.1-qa.json), контент сверен с manifest;
  [два Windows-процесса по UDP — 16/16 PASS](evidence/network-v1.3.1.json).
- Android [собран](evidence/android-build-v1.3.1.json): `Builds/Android/SectorLab-v1.3.1.apk`,
  34 486 228 байт, SHA-256 `DAF6CF754AA7B3636AAB270322F6EB9FF12B59F0AF23D48FFDC6F6E146E15317`.
  `aapt2`: versionName 1.3.1, versionCode 5, target SDK 36, arm64-v8a; оба бандла и каталог сверены.
- Служебные правки сборки (`preloadedAssets`, пересериализация `PC_RPAsset`) возвращены, версия сохранена.
  Входы тестов отличаются от сборки только строкой версии в `ProjectSettings`.

**Физический Android (первый запуск 1.3.1):** владелец подключил телефон. `install-android` установил APK,
хеш установленного `base.apk` совпал с локальным SHA-256, игра запущена. Через 15 с снимок экрана
показывает идущий матч: все шесть бойцов загружены из бандлов (R-07 подтверждён на устройстве),
работают HUD, захват/спор узлов, здоровье и отсчёт возрождения; безопасная зона учитывает вырез экрана.
В логе нет ошибок загрузки; `ClassNotFoundException` для `AssetPackManager` — штатная проверка
Play Asset Delivery в APK без Play Core.

**Ручная проверка владельцем:** несколько партий с «Ещё бой», сворачивание и возврат, жесты и звук —
по сообщению владельца, в порядке. Сетевая игра по Wi-Fi не проверялась.

**Замер 10 мин** ([JSON](evidence/v1.3.1-phone.json), [выборки](evidence/v1.3.1-phone.csv),
[кадры](evidence/v1.3.1-phone-frames.csv)): APK 1.3.1 на устройстве, Android 11, игра на экране
386/386 выборок, автоматическая нагрузка — ИИ против бездействующего игрока, 13 автоматических
«Ещё бой» (партия ≈ 42 с, все перезапуски прошли).
- **29,98 FPS**, медиана кадра 33,3 мс, p95 50,0 мс, пауз дольше 1 с нет. Это упор в ограничение
  Unity по умолчанию (30 FPS на мобильных, `targetFrameRate` не задан); запас до 60 FPS не измерен.
- CPU в среднем **36 %** одного ядра. Память PSS **287–294 МиБ**, без роста за 13 перезапусков.
- Время GPU и выделения GC в релизном APK недоступны. Автоматическая нагрузка — не живая игра.

Замер выявил ошибку инструмента: имя задачи с точками ломало `Path.with_suffix`, CSV записался
как `v1.3.csv`, а проверка «отчёт уже есть» смотрела не тот файл. Исправлено: имена строятся целиком,
все три файла проверяются до подключения к устройству, CSV открываются без перезаписи;
2 новых Python-теста (всего 12). CSV этого замера переименован, модель устройства в JSON скрыта
по прежней просьбе владельца и больше не записывается инструментом.
Облачный CI не запускался.

### Исправления ревью (27.10.2026)

После комплексного ревью владелец разрешил выполнить весь план исправлений. Исправлены:

- **R-07/R-06:** Android и Windows явно выбирают target и собирают контент до Player build;
  manifest и артефакт сравниваются по путям, размерам и SHA-256. Каталог без бандлов отклоняется.
  Публичная настройка layout убирает диалог первого content build; readiness polling ждёт domain reload.
- **R-01:** ошибка смены сетевой роли пересоздаёт Offline-матч с ИИ и сохраняет понятное сообщение.
- **R-02:** клиент рисует авторитетные линии новых выстрелов, не запускает собственный бой и не
  повторяет историю при подключении, дубликате, смерти, респауне или новом матче. Протокол **v3**,
  несовместим с v1/v2; обоим участникам нужна одна версия игры (сейчас 1.3.1).
- **R-04/R-05:** сетевая фикстура восстанавливает настройку обучения; повторное имя проверки
  отклоняется до Unity и не перезаписывает JSON/CSV.
- **A-01:** все готовые выстрелы тика собираются до применения урона. Возможна взаимная гибель;
  проверка обеих последовательностей регистрации проходит. Полные тактические матчи проходят.
- **R-03:** сохранён ручной GameCI с фильтром собственных тестовых сборок и явным preflight;
  автоматический облачный Unity-gate отложен владельцем, обычные проверки выполняются локально.

Новые решения: [ADR-021](adr/021-explicit-platform-content-and-artifact-validation.md),
[ADR-022](adr/022-simultaneous-ready-shots.md), [ADR-023](adr/023-replicated-shot-endpoints.md).
Обновлены правила и архитектура без новых runtime-сервисов и обновлений зависимостей.
Прежние отчёты не переписаны. В частности, прежнее утверждение о полноте Android 1.2.0
было неверно: присутствия `assets/aa/` оказалось недостаточно.

Исправления разделены на небольшие коммиты; результаты тестов и сборок сохранены с исходными
`sourceHead` и хешами входов, без подмены их на последующие commit SHA. Владелец подтвердил
коммиты и отправку в `origin/main`. Архив для анализа скопирован в Downloads; в Git он не включён.

После внешнего разбора архива актуализирован README: кандидат 1.3.0, 260 тестов,
16 UDP-проверок и ограничения зависимости от FPS. Предложенный пилот облачного CI отменён
после прямого отказа владельца от сервисов Unity. Новые облачные проекты, подписки, ключи
и интеграции не создавались. Ветка `main` пока не защищена, repository rulesets отсутствуют.
Текущее направление — локальная проверка игры и физический Android, [24 ADR](adr/).

## Известные ограничения

- Одна карта, 3×3, без прогрессии и экономики. Графика — примитивы Unity.
- Сеть: один соперник, только IPv4 в одной локальной сети, без шифрования и аутентификации.
  Хост проверяет каждый приказ (`MatchCommands`), но канал не защищён.
- Сборка Android может менять `preloadedAssets` в `ProjectSettings.asset`. Проверять diff и
  возвращать только служебную правку, сохраняя намеренные настройки/версию.
- Для ручной Player build в обход `sl.py` явная сборка и проверка контента остаются обязанностью
  разработчика. QA-команды включаются только с `--qa` и не должны попадать в обычный APK.
- Поведение на физическом Android, реальном Wi-Fi с потерями и облачном Unity runner в этой
  сессии не подтверждено. Производительность Windows/Editor не выдаётся за мобильную.
